# EVA — AI SOURCE OF TRUTH (AI-FIRST ARCHITECTURE)

## Purpose

Define EVA as an AI-first commercial system.

---

## Core Decision

EVA is NOT rule-based.

EVA is:
→ prompt-driven
→ context-aware
→ dynamically generated

---

## System Philosophy

AI-first  
Prompt-first  
Backend as guardrail  
Sales Brain as commercial intelligence  

---

## Message Flow

message  
→ build context  
→ build prompt  
→ AI generation  
→ validation  
→ response  
→ memory  

---

## Roles

### AI
- generates conversation
- adapts tone
- handles natural language

---

### Backend
- validates inputs
- enforces rules
- protects system

---

### Sales Brain
- detects intent
- detects stage
- guides AI
- injects business logic

---

## What We DO Build

- context builders
- prompt builders
- validators
- memory systems
- metrics

---

## What We DO NOT Build

- hardcoded conversations
- rigid reply trees
- static flows

---

## Prompt Structure

A prompt must include:

- identity (who EVA is)
- business context
- tone
- rules
- customer context
- product catalog
- output instructions

---

## Multi-Tenant Rule

Each business has its own:

- prompt configuration
- tone
- catalog
- rules

---

## Memory

System must store:

- conversations
- leads
- customer signals
- events

---

## Golden Rule

If you are hardcoding responses,
you are breaking the system.

---

## Final Definition

EVA is:

An AI Sales Assistant that converts conversations into revenue using dynamic prompts, memory, and business logic.
